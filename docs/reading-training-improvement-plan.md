## 1. 目标与依据

将现有十步页面完善为一份持续积累、可回看、可修订、可核验的阅读记录。每一步使用前一步的成果，用户不因 AI 失败丢失答案，也不因回看而删除历史。

本方案依据当前工作树、用户最新十步流程及本轮代码审查。现有工作树包含未提交的训练改动和未跟踪的 `store-assets/`，实施时必须重新核对并保留，不得覆盖或一并提交无关文件。

本方案取代以下旧文档中与新流程冲突的未来开发约定，但不改变历史记录的课程含义：

- `reading-training-10-step-workflow.md` 中“隐藏假设与逻辑漏洞分成两步，费曼与复盘合一步”的顺序。
- `reading-training-implementation-plan.md` 中以旧八轮升级为旧十轮为目标的任务及已完成标记。
- 旧方案中要求第三步分析全部段落、仅首题固定、回看通过撤销完成的约定。

新流程固定为：预读 → 全文通读 → 重要段落三句法 → 全文三点总结 → 5W1H → 假设与证据风险 → 核心论证 → 完整论证 → 费曼解释 → 全文复盘。

## 2. 范围与实现选择

### 2.1 推荐方向

复用 React、TypeScript、Chrome MV3、本地存储、现有 AI Provider 和 Node/Vite 检查脚本。先修复数据可靠性，再建立版本化会话和非破坏式修订，随后完善各步骤及 AI。

最小选项是只修复保存、索引和提示词问题，保留十个独立表单。它适合作为第一批修复，但无法满足逐步关联、回看修订和完整复盘，因此不作为最终交付。

不引入通用工作流引擎、新状态管理库、账号服务或新的后端。步骤定义集中管理，业务转换使用纯函数，持久化由现有后台入口负责。

### 2.2 保持的边界

- Chrome/Edge MV3；Side Panel 负责入口，完整阅读训练在训练标签页。
- 数据保存在 `chrome.storage.local`；文章按用户操作抓取。
- 四种已有界面语言同步维护。
- 无新增遥测、跨设备同步、外部搜索、自动事实核查、OCR 或模型自动补写学生答案。
- 不开发通用富文本批注编辑器。第一版用段落卡、来源块选择和短引文实现依据关联。
- 不新增密钥或第三方账户要求。直接 AI 使用已有设置；没有密钥仍可保存并完成本地训练。桥接评分沿用用户主动复制、导入流程。
- 本计划不授权 git 提交、推送或商店发布。

### 2.3 成功标准

1. 用户无需读完整篇文章即可完成预读并进入通读。
2. 十步都有清晰的主任务、输入、前序成果和完成条件。
3. 第三步只要求所选重要段落；全文总结仍以全文为范围。
4. 第七、八步明确处理同一条论证。
5. 回看不修改记录；修订保留旧版本与旧反馈。
6. 已保存、正在保存、保存失败状态可辨认；失败时不得显示已保存。
7. 课程变更不重新解释旧步骤，原有记录和草稿可查看、导出。
8. AI 反馈绑定准确的文章快照、步骤及答案版本；迟到响应不能覆盖新答案。
9. 本地完成与获得 AI 反馈分别统计，不把未评分显示为零分。
10. 真实浏览器验收与自动检查分别列证据，构建通过不能代替交互验收。

## 4. 固定的产品行为

### 4.1 阅读工作区

- 宽屏显示原文与当前训练卡，窄屏以“原文 / 训练”切换，保留阅读位置。
- 顶部显示当前步骤、完成进度和保存状态。
- 当前卡优先展示一个主任务。说明、示例、检查清单默认折叠。
- 已提取的元信息以可核对的摘要显示，展开后编辑，避免十个大输入框同时出现。
- 前序成果以折叠卡呈现；点击关联依据定位原文块。
- 展开历史可看原题、答案版本、反馈和参考答案，不只显示总分。
- 不以停留时间或滚动到底假装证明用户已阅读。时间仅作建议，不设倒计时门槛。

### 4.2 保存、继续、评分、修改

| 操作 | 明确行为 |
| --- | --- |
| 自动保存 | 保存草稿；显示状态；失败保留输入并提供重试 |
| 保存并继续 | 校验本步最低结构要求；保存成功后标记本步完成并前进；不依赖 AI |
| 请求 AI 反馈 | 保存当前内容后生成不可变答案版本；请求绑定该版本；失败不撤销保存 |
| 查看参考答案 | 保持既有规则：已获得反馈且已配置直接 AI 后可生成；针对对应答案版本展示 |
| 回看 | 只改变当前查看步骤，不删除记录，不降低已完成进度 |
| 修改并保存 | 创建新版本，保留旧答案和旧反馈；受影响后续步骤标为待复核 |
| 确认仍适用 | 用户检查后解除后续记录的待复核标记，不自动重评分 |
| 重新开始 | 明确确认后新建一份训练，旧记录归档，不以清空数据实现 |

参考答案的 ChatGPT 桥接属于后续功能，不在本批扩展，避免把此前用户已接受的行为改掉。评分桥接继续可用。

### 4.3 完成状态

- 编辑状态：未开始、草稿、已完成、待复核。
- AI 状态独立：未请求、请求中、成功、失败。
- 最终完成要求十步当前有效记录满足完成条件，且不存在待复核步骤；不要求全部获得 AI 分数。
- AI 分数低不自动阻止继续。缺少必填结构或保存失败才阻止本步完成。
- 步骤进度、评分覆盖率分别显示；测试会话不计入正式成长统计。

## 5. 十步任务规格

| 步骤及稳定 ID | 输入和成果 | 完成条件 | 下一步如何使用 |
| --- | --- | --- | --- |
| 1 `preview` | 标题、副标题、作者、来源、日期；首末段观察；结构线索；预计问题；未知内容 | 核对元信息状态；填写首末段观察和阅读问题；缺失线索说明状态 | 第二步显示阅读问题和预读观察 |
| 2 `quick-browse` | 全文结构概述；每段功能标签；首末句定位；重要段落候选 | 每个正文/引用段落标记功能或“暂不确定”；完成结构概述并确认已通读 | 第三步复用段落列表和候选段落 |
| 3 `three-sentence` | 所选段落的“说什么／理由／想说明什么”；段落作用；依据 | 至少选一段；仅所选段落需要完整记录；理由允许未交代 | 第四步旁边展示所选段落记录，并提醒总结全文 |
| 4 `three-points` | 三个短要点；各自依据；覆盖检查 | 正好三点；每点符合长度规则；每点有依据；用户核对是否重复及遗漏全文 | 第五步用三点作为提问背景 |
| 5 `questions` | 问题列表及5W1H类别；选中1–2个；重要性；相关段落；已回答/未回答 | 至少一个关键问题；填写重要性和原文回答边界；不要求六类全问 | 第六步围绕选中问题检查风险 |
| 6 `assumptions` | 主张、证据、默认前提、前提不成立的影响、其他解释、证据不足、不确定性 | 选定一个检查对象；区分明确陈述/未说明/推理风险；允许说明暂未发现风险 | 为第七步推荐待分析主张，用户确认 |
| 7 `toulmin-simple` | 一条核心论证的主张、证据、保证；每项的依据类型 | 锁定一个论证；区分原文明示、上下文推断、未交代；推断给出理由 | 第八步绑定同一论证 ID |
| 8 `toulmin-full` | 只读展示第七步三项；补支撑、限定、反驳；薄弱点和核实点 | 三项均有状态或内容；支撑针对保证；反驳区分作者回应与读者提出 | 第九步选择该论证或一个核心概念 |
| 9 `feynman-review` | 通俗解释；例子或自创类比；适用边界 | 说明对象、解释、例子和边界；自创类比有标记，不充当原文证据 | 第十步呈现解释和自查结果 |
| 10 `final-review` | 汇集主旨、三点、论证、前提、强证据、薄弱点、不确定性、重读位置 | 用户核对汇集记录；补充个人判断；所有待复核事项有明确处理 | 形成可导出阅读记录 |

### 5.1 字段规则

- 事实类状态：已找到、提取未获得、已核实原文未提供。不得将提取失败默认为原文不存在。
- 分析类状态：原文明示、依据上下文推断、原文未交代。推断必须标注，允许合理推断，禁止伪装成引文。
- 个人任务类：问题、重要性、类比、未知内容使用独立说明，不能统一提示“原文未提供”。
- 确实不适用时记录理由，不强迫编造因果、隐含假设或反驳。
- 非论说文仍可进行理解、总结和解释；第六至八步允许注明“未发现可拆解论证”并引用判断依据，作为有效完成。
- 三点总结中文/日文/韩文按最多15个非空白可见字符计数，英文按最多15个空白分隔词计数；标点随字符计数，序号不计入。界面明确显示当前规则，服务端同规则。
- 普通长文本字段最多800字符；三句法单项最多2,000字符。完整结构化答案序列化上限统一36,000字符；单字段和全步限制在输入、保存、提交、AI请求及导出路径一致。达到上限阻止新增输入并说明，不静默截断已有内容。
- 旧记录超出新限制时仍可查看、导出，不能在读取时截断或覆盖。
- 段落标签使用固定可选项并允许“暂不确定”；不要求用户重复抄写整个段落。
- 首末句允许自动建议，但必须可更正；引用应是原文中的连续片段，不依赖句子分割算法作为事实。

### 5.2 教学规则纠偏

- “没有说明”不等于“论证错误”；检查结果可以是没有发现明显问题。
- “A可能影响B”不自动推出“没有A就一定没有B”。隐藏前提示例不得强化成必然关系。
- 区分经验材料与机制解释；把一句话放入证据栏并不证明它已被证实。
- 第三问是段意或作者意图概括，“全文作用”是结构位置，两者分别记录但可复用用户文字，不强制同义重复。
- 自创类比用于解释，不能用来证明文章主张。

## 6. 数据与模块设计

### 6.1 单一课程定义

`src/training/lessons.ts` 统一维护稳定 step ID、顺序、任务文案键、字段定义、完成规则、评分要求和前序成果。UI、后台校验、AI提示和导出均引用这份定义，取消 App 与 lessons 各自维护字段集合。

存储以 step ID 定位，索引仅用于显示顺序。课程版本与存储格式版本分别记录，不再用 `reading-10` 一个值同时表达所有含义。

### 6.2 新会话结构

新格式命名为存储版本3，使用独立键 `trainingSessionsV3`；课程版本使用 `guided-reading-10-v1`。主要实体：

| 实体 | 必要内容 |
| --- | --- |
| 会话 | session ID、article ID、课程版本、文章快照标识、当前查看 step ID、测试标记、创建/更新时间 |
| 文章快照 | 标题和元信息及可用状态、完整来源块、稳定 block ID、显示段号；本次训练内不可变 |
| 步骤记录 | step ID、编辑状态、当前草稿、当前答案版本 ID、完成时间、待复核来源 |
| 答案版本 | version ID、结构化内容、用于导出的文字、所依赖前序版本、保存时间 |
| 来源关联 | snapshot ID、block ID、显示段号（如有）、连续短引文；不只保存易漂移索引 |
| 核心论证 | argument ID、主张/证据/保证、支撑/限定/反驳、依据类型和来源关联 |
| AI 结果 | request ID、session/step/answer version、反馈或参考答案、状态和错误类别 |

只在明确提交或修改完成时创建答案版本；输入中的自动保存更新当前草稿，不为每个按键创建历史版本。

文章发生变化时创建新快照/训练，不自动让旧引文指向新正文。第一版不实现跨文章版本自动对齐。

### 6.3 数据流

```text
课程定义 → 训练界面 → 后台消息 → 会话存储
    ↓                      ↓          ↓
AI任务约束 ← 文章快照 + 答案版本 ←───────┘
    ↓
AI响应校验 → 按请求身份保存 → 反馈展示

会话存储 + 文章快照 → 回看 / 复盘 / 导出
```

### 6.4 保存与并发

- 每个写请求带 session ID、step ID、草稿修订号；后台拒绝过期修订，不能把旧步骤草稿写入新步骤。
- 继续、修改步骤或请求评分前，等待当前保存确认；失败停留并保留输入。
- 复用现有 mutation queue；它负责串行写入，修订号负责语义上的过期检查，两者不能相互替代。
- AI 请求携带答案版本 ID；生成期间修改内容，返回结果归旧版本，当前页面标注版本，不覆盖新草稿。
- 同一请求重复点击/导入按 request ID 幂等保存。
- 组件卸载不依赖最后一次异步保存必定完成；界面明确展示尚未保存，站内导航先等待保存。
- 存储配额失败不删除历史换空间；显示失败原因，允许导出和用户主动管理记录。

### 6.5 回看、修改和依赖失效

- “回看”与“编辑历史答案”分开。
- 修订步骤N后，将已经完成的后续步骤标为待复核，保留内容；第一版采用这个保守规则，不开发动态依赖图引擎。
- 第七、八步始终共享 argument ID；更换主张时第八步旧内容仍保留但必须复核。
- 反馈对旧答案仍有效，但在新答案界面显示“对应旧版本”，不可算作新答案的评分。
- 后续记录确认仍适用后记录新的前序版本关联；用户无需为无关修改重新填写整套内容。
- “再巩固一轮”独立保存为附加练习，不复用第十步草稿、不改变十步完成数。

## 7. 历史记录与回滚

### 7.1 分类规则

- `trainingSessions` 中的旧八轮保留只读查看和导出。
- `trainingSessionsV2` 包含旧十步与当前未版本化的新十步，不能仅凭数组长度或 currentStep 推断课程。
- 有明确且一致的 step ID/index 组合时，按对应历史课程解释；存在冲突或证据不足时标为“历史训练，课程版本未确定”，保留原问题和答案，不猜测阶段名称。
- 历史参考答案只展示已有结果；课程无法确定时不重新请求 AI，避免使用错误步骤评分。
- V2 原始存储不自动改写。新训练写 V3；用户可从历史记录复制内容到新步骤，但系统不伪造已完成状态。
- 保留当前已有 V2 结构化字段和文本。原文字段与结构化内容冲突时都可查看，禁止空标签覆盖文本。

### 7.2 安全落地与回滚

- 第一批先修复当前读取/自动保存的数据覆盖，再接入 V3。
- 新版本先读取 V3；没有时展示原始历史记录及“开始新版训练”入口，不把历史记录隐藏。
- 多份训练用 session ID 区分，同一文章可以有历史归档和当前训练。
- 回滚应用时 V3 数据保留；旧构建可能看不到 V3，必须明确告知，不能声称回滚后仍能编辑新记录。
- 回滚不删除任何存储键，不做逆向覆盖转换。
- 删除文章仍需确认，明确说明同时删除哪些关联会话；由一条后台操作完成关联清理并处理失败。
- 不在本次普通升级时要求用户重置扩展或清除浏览器数据。

## 8. AI 与引用规则

- 所有十步主任务固定。AI 追问显示在反馈内，不回写主任务和步骤顺序。
- 每步提示词包含任务、字段含义、允许的缺失情况、评分标准、当前答案版本及相关前序成果。
- 原文保留完整文本块类型、标题、列表、图表文字、强调信息和元信息可用状态。图片只有可获取的文字/alt，不假装模型看到了图像。
- 预读评分限定在预读线索范围，不使用正文中后部材料要求用户提前知道结论。后续步骤允许全文上下文，三句法评分明确限定所选段落。
- 过长上下文不静默删除全文。明确提示模型容量限制或请求失败，保留本地继续能力。
- 保留现有四个评分维度；按步骤启用相应维度，并补充具体评分标准，未测项为 null。
- 本地校验检验结构、引用位置、版本身份及长度；不假装规则校验能够证明语义正确。
- 自创类比单独标记并允许；AI 评价对应关系与边界，不能把类比要求为逐字原文引用。
- 依据校验支持正文及非正文来源块，统一使用来源 ID；旧的段号引用经适配器读取。
- 错误区分连接/超时、JSON格式、引用不匹配、步骤或版本不匹配；给出对应重试说明，不打印密钥和整份敏感材料。
- 桥接请求与导入使用同一套步骤、版本及引用校验。输入变化后旧请求不能成为当前版本反馈。
- 参考答案从已提交版本生成，包含当前步骤要求和所选段落；不污染学生答案，不自动填入表单。

## 11. 验证方案

### 11.1 自动验证

优先现有 Node/Vite 检查脚本，不新增测试框架。对已复现缺陷新增能证明错误行为的用例；修复前后分别运行红/绿验证。共享工作树不可为此回退或stash，必要时用隔离临时副本。

必须覆盖：旧八轮、旧十轮、当前未版本化十轮、无法判定的历史记录；旧文本草稿；每步保存刷新；回看与修改；36,000字符边界；保存失败；两标签页过期修订；迟到AI结果；重复提交/导入；所选段落变更；单段/单句/无论证文章；标题/图表/列表依据；参考答案与自创类比；多语言长度规则；各格式导出。

相关检查先运行，最终集成运行：

```sh
pnpm check:training-flow
pnpm check:storage-concurrency
pnpm check:article-format
pnpm check:pre-reading
pnpm check:i18n
pnpm check:ai-http
pnpm check:provider-settings
pnpm exec tsc -b --pretty false
pnpm lint
pnpm build
node scripts/check-extension.mjs
git diff --check
```

若环境仍把 `pnpm lint` 改写成错误包装命令，记录该失败并运行 `pnpm exec oxlint .`，分别报告，不把包装错误算成代码通过。只在依赖变化时安装依赖。

### 11.2 浏览器验收

Chrome和Edge分别验证：新文章预读、长文章按段标签、选段分析、无AI完成十步、直连AI、桥接导入、修改前序、刷新恢复、两标签页编辑、断网/超时、参考答案、导出及历史记录。

检查窄侧栏入口、完整训练页、窄窗口布局、键盘操作、中文输入法、保存提示和错误后输入保留。

当前工具对 `chrome-extension://` 的读取曾被安全策略阻止。不得绕过限制；实现时可做普通本地预览及模拟测试，但真实扩展验收由可用的授权测试环境或用户操作完成，并记录明确证据，未完成时保持未勾选。

### 11.3 完成定义

- 代码、类型、任务文案、AI规则、导出和文档一致。
- 所属清单任务有测试或手工验收证据，不能以“代码存在”勾选完成。
- 历史记录不被覆盖；失败可恢复；无新增权限和外部服务。
- 本地与AI模式均经过对应验收；未验证项明确标注。
- 每批交付列实际变更文件、检查结果、已知限制和下一批入口。
- 发布或提交需另按用户指令执行；验收通过本身不授权发布。
